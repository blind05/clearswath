# ClearSwath — two-day submission polish runbook

The controlling target is the **three-minute recorded hackathon demo**, not feature expansion. Review `docs/video/SCRIPT.md` first and confirm that every claim matches `README.md`, `docs/STATUS.md`, and real app runs.

## 1. Reproduce the source footage

```bash
uv sync
cd web-app && npm ci && npm run build && cd ..
uv run pytest
uv run python scripts/record_demo.py
```

The recorder writes `data/video/demo.webm`, a PNG for each beat, and `data/video/takes.json` containing approximate shot timecodes. Visually inspect each take; the timestamps are **edit aids**, not frame-accurate EDL. Its saved demo model outputs are cached authentic runs, not new live inference.

Record additional real-screen takes for the original label excerpt, conditional rule interactions and export checks. Cut the strongest moment first. No simulated browser clicks or fake model wait spinners. Keep original captures untouched as evidence.

## 2. Picture editing

Make a 2:36 target cut in a non-linear editor (DaVinci Resolve, CapCut, Premiere), or Remotion if its rendering pipeline is already validated. Export the silent, fully edited picture as `data/video/cut.mp4`.

- Actual result first: Montana drone imagery + magenta spot-spray map within 7 seconds.
- Captions should explain what the viewer sees, not narrate abstractions or repeat all words.
- 16:9 at 1920×1080; minimum 30fps delivery. Favor close-ups of real content so the label quotes can be read.
- Hard cuts are default. Use only purposeful map overlay reveals, masked before/after cuts, or very restrained pushes on static screenshots.
- Screen recordings must clearly identify cached demo vs live actions; show the same real app and screenshots that judges can inspect.
- Keep movement off the website by default. Cinematic motion belongs in the edited film.
- Avoid generic stock farm videos, invented drone footage, stock UI animations, endless scrolling, excessive jump zooms or impact statistics without a test reference.

## 3. Original music and sound FX

This repository includes a small original soundtrack synthesizer:

```bash
uv run --with scipy python scripts/create_demo_audio.py
```

This writes `data/video/audio/clearswath_music_full.mp3`, `clearswath_music_under_vo.mp3`, and `clearswath_sfx_timeline.mp3`, plus lossless WAV versions.

The under-VO bed is intentionally quiet; the full version is for short gaps and visual beats. The FX timeline is only a proposed timing guide, so move or omit cues to match actual transitions. No external music samples or sound libraries are required.

Record natural human narration in a quiet space as `data/video/voice.wav`. The script is in `docs/video/SCRIPT.md`. Do not force the speech to fit the written second marks at the cost of clarity: revise the cut.

```bash
python scripts/mix_demo_audio.py \
  --video data/video/cut.mp4 \
  --voice data/video/voice.wav \
  --music data/video/audio/clearswath_music_under_vo.mp3 \
  --sfx data/video/audio/clearswath_sfx_timeline.mp3 \
  --output data/video/clearswath_submission.mp4
```

The mixer **does not edit picture** or create narration. It combines supplied recordings, applies a gentle speech compressor, and prevents clipping. Listening is mandatory. Compare spoken-word audibility on laptop and phone speakers. If the music is too quiet, adjust its stem or the mix, don't overcompress the voice.

Validate the final export:

```bash
ffprobe -v error -show_entries format=duration:stream=codec_name,width,height \
  -of default=noprint_wrappers=1 data/video/clearswath_submission.mp4
ffmpeg -hide_banner -i data/video/clearswath_submission.mp4 \
  -filter_complex ebur128=peak=true -f null -
```

No final movie exists until the audio and picture are actually exported and reviewed; files generated by the scripts are inputs, not evidence of a complete submission.

## 4. Product experience audit

Keep the industrial label-first design in `DESIGN.md`. A small change now gives first-time visitors a direct **Explore the Montana example** action rather than only confronting them with a form.

Check **desktop 1440 and 1280px** and **mobile 390px**:
- Clear hierarchy: product job-to-be-done → demonstration → mapped result → quoted reason → export.
- No console errors, blocked inputs, horizontal scroll, blank map, overlapping navigation, or ambiguous busy states.
- Open the demo on a fresh session without auth, confirm result and map fully render, test legend toggles, agent trace, conditional rule controls, and the corrected South Dakota field.
- Verify focus-visible, keyboard navigation, color contrast, reduced motion, map legend text and loading/failure recovery.
- Preserve safety language: “Adjust”, “Do not spray”, “No conflicts in checked rules” and explicit unchecked conditions. The product is not a safety or legal clearance authority.
- Give every essential click honest behavior. Remove any visible fake UI or claims the app cannot verify.
- Verify branding remains visually distinctive: IBM Plex typography; document-excerpt aesthetic; 400px evidence panel; large map; magenta spray cells. No colorful gradient hero, fake analytics, stock dashboard metrics, unnecessary shadows, decorative AI sparkle badges, or arbitrary card grids.

## 5. Final release gate

1. Verify the actual hackathon participant guide, public repo/video links, and Wednesday November 4, 2026 at 9pm ET deadline.
2. Run `uv run pytest` and `cd web-app && npm run build`. Resolve any failures before merging.
3. Check `docs/STATUS.md` for real-vs-unverified features and include demo limitations in the README.
4. Independently open the live app and uploaded video using an incognito session (Render free hosting may cold-start).
5. Video under 3 minutes; clean audio; actual product interactions; proof of Meta model contributions; accurately labeled cached runs; tested map output; licensing and source attribution.
6. Treat any product change as a code change requiring smoke tests, not as marketing polish. Do not let the video or UI compromise the already functioning demo.

The deliverable is **a working product, public repo, and accessible finished film with voice, music, proof, and an honest source trail**. No hackathon win can be guaranteed.
